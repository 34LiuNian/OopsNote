# 题图自动版面识别调研方案

状态：调研方案（不改变当前生产链路）  
日期：2026-07-31

## 1. 背景与结论

当前批量题图流程要求用户在整页图片或 PDF 上手动框选。现有 `ocr_image` 的输入契约是“一张已经确认的单题图片”，它会在发现多道顶层题时标记 `multiple_questions`，但不负责页面分割。因此，直接扩大 OCR 提示词不能解决版面识别，反而会把页面分割、题目识别和内容抽取混在一个不可审计的模型输出中。

本次调研建议采用 **版面检测 + 规则分组 + 人工确认 + 现有单题 OCR** 的混合方案：

```text
整页题图/PDF
    -> 版面检测（候选块、类别、置信度）
    -> 题目区域分组（列顺序、题号、图文归属）
    -> Web 预览与人工确认/调整
    -> 生成已有 batch segment / 单题任务
    -> 现有 ocr_image -> solve -> verify -> finalize
```

版面识别只产生可回滚的候选几何数据，不直接生成 `Problem`、不写 OopsMark 正文，也不改变 ManagedAiRunner 的生命周期。

## 2. 不变量与边界

### 2.1 必须保持的不变量

1. 原图或原始 PDF 是唯一校对依据；裁剪图是可重新生成的派生资产。
2. 所有坐标使用现有归一化矩形 `{x, y, width, height}`，并保留来源页索引。
3. 自动识别结果必须显式带有模型/规则版本、置信度和状态；低置信度不能伪装成已确认题目。
4. 只有用户确认后的区域才能创建任务；一次任务仍只接收一道题的裁剪图。
5. 同一来源哈希和同一检测版本重复运行必须幂等，不能重复创建任务或覆盖人工调整。
6. 检测失败、区域不完整、多题合并和阅读顺序不确定必须进入人工复核，而不是自动降级为“整页 OCR”。

### 2.2 不在本次范围内

- 解题、判对错、学生作答识别和 OopsMark 内容生成。
- 从几何上的 `figure` 区域自动生成 TikZ、公式或结构化表格。
- 删除现有手动框选入口。
- 在同一 AI run 内从 Pi 切换到 Hermes，或为版面识别增加隐式后端回退。

## 3. 候选技术路线

| 路线 | 作用 | 优点 | 主要风险 | 调研结论 |
| --- | --- | --- | --- | --- |
| 传统 CV（投影、连通域、行聚类） | 产生文本块和空白分隔 | CPU 快、可离线、容易解释 | 对拍照倾斜、手写、跨栏和公式脆弱 | 作为可复现基线和故障兜底，不单独上线 |
| PaddleOCR PP-StructureV3 / Layout Detection | 检测文本、标题、表格、公式、图片等版面块 | 有现成推理接口，可本地部署；官方布局检测覆盖 20 类常见元素 | 通用文档类别不等于“题目区域”；需自行合并题干、选项和附图；模型包和运行时体积需评估 | 首选候选生成器，先做零样本基线，再考虑少量领域微调 |
| 视觉大模型输出框 | 解释题号、子问、图文关系 | 对复杂语义和异常排版更灵活 | 延迟、费用、非确定性、隐私和坐标稳定性；不能作为唯一真相 | 仅用于中低置信度复核或离线标注辅助 |
| 混合方案 | 本地检测 + 几何/题号规则 + 可选视觉复核 | 保留离线能力和可解释性，复核范围可控 | 需要定义候选块到题目区域的分组规则 | 推荐方案 |

PaddleOCR 官方文档将版面检测定义为对文档图片内容进行解析和分割，并列出文本、表格、公式、图片等类别；PP-StructureV3 还提供集成式版面解析管线。参考：[Layout Detection](https://www.paddleocr.ai/main/en/version3.x/module_usage/layout_detection.html)、[PP-StructureV3 Usage](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PP-StructureV3.html)。这些能力说明它适合做“块检测”，不意味着它已经能可靠识别中国试题的完整题目边界，题目分组仍需本项目自己的规则和评测。

## 4. 建议的处理流程

### 4.1 预处理

- 解码图片/PDF 页面，记录原始宽高、方向和页索引。
- 仅做不改变坐标含义的旋转、去黑边和缩放；保留变换矩阵。
- 生成检测分辨率副本，最终框映射回原始像素后再归一化。
- 对超大图设置像素上限和超时，失败时保留明确的 `failed` 状态。

### 4.2 块检测

检测器输出以下最小字段：`bbox`、`kind`、`score`、`reading_hint`。建议类别先收敛为：`text`、`title/number`、`formula`、`table`、`figure`、`header_footer`、`noise`。保留原始模型类别，另加一个 OopsNote 归一化类别，避免 Web 依赖某个模型的标签名。

### 4.3 题目区域分组

1. 按页内阅读方向聚类列；默认从上到下、从左到右，列间距和重叠阈值可配置。
2. 用题号候选（印刷题号 OCR 或数字模式）作为新题起点；没有可靠题号时，用块间距、分隔线和段落连续性生成候选起点。
3. 将相邻题干、选项、公式和附图归入同一题；图表只作为该题的几何子区域，不改变题目正文。
4. 对跨栏、跨页和题号缺失分别标记，不用“最大外接矩形”静默吞并相邻题。
5. 对候选题目按 `page_index + column_index + y + x` 排序，生成稳定的 `question_no` 预览值；用户确认后才固化编号。
6. 计算完整性信号：区域是否触碰裁剪边界、是否存在未归属块、是否与相邻候选重叠、是否包含题号和至少一个正文块。

### 4.4 人工确认

Web 复用现有 batch 连续页面和 `parts[]` 几何模型，新增“自动建议”状态：

- 高置信度：显示候选框，可批量接受。
- 中置信度：显示候选框和原因，必须逐项确认。
- 低置信度或冲突：不自动创建任务，进入手动框选。

人工拖拽、合并、拆分和删除均写回同一个版面分析记录，并标记 `source: manual`。重新运行检测只能生成新版本，不能覆盖已确认或已提交的 segment。

## 5. 数据契约草案

建议先新增独立的 `LayoutAnalysis`，不要把模型字段直接塞进 `BatchSessionRecord`：

```json
{
  "source_file_hash": "sha256:...",
  "source_asset_path": "/assets/source.pdf",
  "detector": {"name": "paddle-layout", "version": "..."},
  "status": "ready",
  "pages": [{"page_index": 0, "width": 2480, "height": 3508}],
  "regions": [{
    "id": "region-1",
    "page_index": 0,
    "bbox": {"x": 0.08, "y": 0.12, "width": 0.42, "height": 0.18},
    "kind": "question",
    "reading_order": 0,
    "parent_id": null,
    "confidence": 0.94,
    "complete": true,
    "source": "detector",
    "review": "pending"
  }]
}
```

`BatchSessionRecord` 仍是用户确认后的任务选择和提交状态；它可以保存 `layout_analysis_id` 与 region ID 追溯，但不复制检测器的全部结果。这样版面检测版本、人工编辑和任务状态各自只有一个权威来源。

建议状态机：`queued -> running -> ready | needs_review | failed`。`ready` 只代表检测完成，不代表题目已经确认；确认后的状态保存在 batch session/segment 中。

## 6. 评测集与指标

### 6.1 数据集

从本地 vault/storage 中抽样并脱敏，首轮建议 150 页：单栏 40%、双栏/多栏 25%、含图表公式 20%、拍照/倾斜/阴影 10%、手写覆盖和异常页 5%。按来源和版式分组切分 train/dev/test，避免同一试卷相邻页泄漏到不同集合。

人工标注：题目外接框、题号、阅读顺序、附图框、是否跨页、是否完整；另标记“无法可靠分割”的页面。

### 6.2 指标

- **完整题目召回率**：每道题是否被一个候选框完整覆盖；这是最高优先级。
- **错误合并率**：两个独立顶层题被合成一个区域的比例。
- **错误拆分率**：一道题被拆成多个区域的比例。
- **框 IoU / 边界误差**：用于衡量裁剪质量，但不能替代完整性指标。
- **阅读顺序准确率**：候选顺序与人工顺序一致的页面比例。
- **附图召回率**：含图题的图形区域是否被保留。
- **人工修正率与修正时长**：接受、拖拽、合并/拆分的比例和中位耗时。
- **性能**：P50/P95 单页延迟、峰值内存、CPU/GPU 依赖、失败率。

### 6.3 暂定验收门槛（需用首轮数据校准）

- 完整题目召回率 >= 97%。
- 错误合并率 <= 1%，错误拆分率 <= 3%。
- 阅读顺序准确率 >= 99%。
- 需要人工大幅重画的页面 <= 10%。
- 普通本地机器 P95 <= 3 秒/页（不含 PDF 解码和任务 OCR）。
- 任何检测失败或置信度不足都必须可见、可重试、可手动接管。

这些是上线门槛候选，不是对通用模型能力的承诺；若“完整召回率”和“错误合并率”冲突，优先保证不漏题并提高人工复核提示。

## 7. 实验矩阵与实施阶段

### Phase 0：样本与标注规范（1-2 天）

- 固定页面、题目、附图和阅读顺序的标注格式。
- 建立 20 页冒烟集和 150 页评测集，记录原图哈希。
- 先跑传统 CV，得到可复现基线和失败样例。

### Phase 1：本地检测器基线（2-3 天）

- 集成 PP-StructureV3 layout detection，仅保存原始块和置信度。
- 实现列聚类、题号起点、相邻块合并和完整性检查。
- 输出离线 JSON/可视化叠加图，不接入任务创建。

### Phase 2：领域规则与对比（2-3 天）

- 比较“题号驱动”“间距驱动”“检测块驱动”三种分组策略。
- 对单栏、双栏、图文混排、公式密集页面做误差归因。
- 记录每个失败样例应由检测器、分组规则还是人工确认解决。

### Phase 3：Web 预览和小流量试用（3-5 天）

- 新增 `LayoutAnalysis` 读写和候选框预览，复用现有 `NormalizedRect`/`parts[]`。
- 只允许用户确认后创建 batch segments；保留“一键全部转手动”入口。
- 采集候选接受率、修正时间、失败原因和版本信息。

### Phase 4：可选复核模型（2-3 天）

- 只对低置信度、边界冲突或题号缺失区域调用视觉复核。
- 复核输出必须回到同一个 `LayoutAnalysis` 版本，不能直接写任务或 OopsMark。
- 若复核没有显著降低人工修正率，则不保留该依赖。

## 8. 风险、成本与决策点

| 风险 | 处理方式 | 决策点 |
| --- | --- | --- |
| 通用版面类别不等于试题边界 | 以完整题目召回、错误合并为主指标；必要时补充少量领域训练 | Phase 2 后决定是否微调 |
| 公式、表格和手写覆盖导致块断裂 | 保留相邻块和不确定区域，交给人工确认；禁止静默补写 | 是否允许自动接受 |
| 模型体积、安装和 CPU 性能 | 先测本地机器 P95/峰值内存；提供模型版本锁定 | 是否纳入默认安装 |
| 云端视觉复核的隐私和费用 | 默认关闭、仅显式配置；发送最小裁剪区域；记录调用和失败 | 是否进入试用 |
| 版本升级造成框漂移 | 版本写入分析记录，固定评测集做回归 | 通过后才能替换默认模型 |
| 自动候选覆盖人工编辑 | 用新分析版本隔离，已确认 segment 永不被重写 | 作为上线硬门槛 |

## 9. 交付物与下一步

调研阶段应交付：

1. 标注规范和脱敏评测集索引（不把用户原图复制进仓库）。
2. 传统 CV 与 PP-StructureV3 的离线基线脚本、指标表和失败样例图。
3. `LayoutAnalysis` JSON Schema 草案及状态转换说明。
4. Web 候选框交互原型，证明确认、撤销、转手动和重复运行不会破坏现有 batch session。
5. 是否引入领域微调或视觉复核的决策记录。

建议下一步先完成 Phase 0 和 Phase 1，不改生产 API，不创建 AI 任务。只有当评测集达到暂定门槛、且人工修正时长有明显下降后，再提交独立的 Phase 3 实施变更。
