# 组卷两阶段工作流

状态：正式组卷与受控 XeLaTeX PDF 预览/导出已接通

更新：2026-07-27

## 1. 产品边界

OopsNote 区分两类任务：

- **快速重练**：保留现有题目卡片筛选与整卡点击选择，用于快速选择少量错题并生成练习。
- **正式组卷**：使用新的两阶段流程，先形成候选试卷，再进入独立编辑器编排并导出。

两条流程不合并为一个复杂页面。正式组卷的自动选题和手动选题最终进入同一个试卷编辑器。

## 2. 第一阶段：组卷配置

配置面板只负责描述目标试卷，不负责逐题编辑：

1. 从知识树选择知识点。
2. 选择难度比例；提供预设和自定义两层方式。
3. 设置各题型数量。
4. 自动选择候选题并进入编辑器，或跳过自动选题，以空试卷进入编辑器手动选题。

不提供“课时练习”“阶段测试”“综合复习”等出题场景。题量不足时对应位置保持为空，不自动放宽知识点、难度或题型条件，也不增加额外提示逻辑。

## 3. 难度系数

难度系数越高表示题目越难。题号估算只在以下范围内比较，并且总题数必须是录题时明确填写的同一题型区段总题数：

```text
同一原始试卷或批量录题会话
+ 同一章节
+ 同一题型区段
```

暂按题目在所属题型区段中的相对位置估算：

```text
难度系数 = 题号 / 该题型区段总题数
```

例如，选择题第 5/8 题的难度系数为 `0.625`，填空题第 2/3 题的难度系数约为 `0.667`。

- 先按题型分组，再在每个题型内按难度系数从低到高排列。
- 系统绝不从当前已导入题目的数量推断总题数；部分导入、重复导入或筛选后的样本都不能改变已知系数。
- 小题量区段暂不做精度校准。
- 题目可设置 `TaskRecord.difficulty_coefficient_override`；存在覆盖值时，自动选题和草稿快照优先使用它，清空后恢复题号估算。
- 无法识别来源、题号或区段总题数，或题号大于总题数时，题目会明确标记为需要人工处理，且不会被自动选题使用。
- 相同难度不要求确定性排序。

## 4. 第二阶段：试卷编辑器

进入第二阶段时创建持久化试卷草稿。草稿永久保留并自动保存，只能由用户主动删除。

试卷编辑器负责：

- 增加、移除和替换题目；
- 调整题目顺序和题型分组；
- 编辑分值、答题空间和试卷级排版属性；
- 查看试卷结构、难度与知识点覆盖；
- 预览并导出试卷。

题干、选项、答案和解析仍以 Core 题目中的 OopsMark 为唯一内容源。试卷只保存题目引用和试卷级属性；需要修改题目正文时进入题库原题编辑，不创建试卷专属题面副本。

排序规则：

- 初次自动选题后，按题型分组并在题型内按难度系数从低到高排列。
- 用户拖动后的顺序永久保留。
- 替换题目留在被替换题目的原位置。
- 新增题目插入所属题型内符合其难度系数的位置。
- “按难度重新排序”可以放入二级菜单，不作为主操作。

## 5. 页面入口

当前路由职责：

```text
/paper-builder          快速重练
/papers                持久化试卷草稿列表
/papers/new             正式组卷配置
/papers/{draftId}/edit  试卷编辑器
```

正式组卷配置页的“跳过，手动选题”仍会创建空的持久化草稿，再进入试卷编辑器。

## 6. 已接入配置

- 知识树使用 XKW 清洗后的 `oopsnote/catalog/data/knowledge_trees.json`，正式组卷只显示 `core` 范围。
- 难度区间为容易 `0～0.5`、适中 `0.5～0.8`、困难 `0.8～1.0`。
- 容易预设为 `80% / 20% / 0%`，适中预设为 `50% / 45% / 5%`，困难预设为 `35% / 40% / 25%`。

## 7. 正式导出边界

正式导出以持久化 `PaperDraft` 和 Core OopsMark 为唯一真相：

```text
PaperDraft + TaskRecord / Problem
             |
             v
       PaperDocument
             |
             v
   paper.tex + managed assets
             |
             v
      controlled XeLaTeX
```

- `/papers/{draft_id}/compile` 只从服务端保存的草稿构建试卷，消费草稿顺序、连续题型分组、分值和答题空间。
- `/papers/compile` 保留给快速重组，但也先构建临时草稿并复用同一个 `PaperDocument` 与 LaTeX 适配器。
- 正式导出只接受 `oopsmark-v1`；旧内容、失效题目引用、待审核或缺少源的题图会在启动 XeLaTeX 前明确失败。
- 题图资产由受限 `AssetStore` 解析并复制进一次性编译目录；不允许任意文件路径。
- XeLaTeX 使用 `-no-shell-escape`、受限文件读写、120 秒总时限和两个固定编译 pass。第二个 pass 仅用于解析总页数等交叉引用，不是失败重试。
- 编译失败返回稳定错误码和截断后的原始日志，不会切换排版后端或返回旧 PDF。
- `PaperBundle`（主 TeX 与内容寻址资产）是未来本地编译器和远程 Docker 编译服务的共同输入；远程服务不得重新解释 OopsMark。
