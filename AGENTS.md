# OopsNote project instructions

## Current architecture

OopsNote is a local-first question-management application:

```text
Web / REST
    -> ManagedAiRunner
       -> PiRpcRunner / pi_agent_rust (default)
       -> PiRpcRunner / upstream Pi (diagnostic fallback)
       -> HermesRunner (temporary fallback)
    -> shared restricted Python MCP
    -> Core JSON stores / assets / Obsidian sync
```

- The default is a bounded pool of three long-lived pi_agent_rust JSONL RPC processes. Each task must complete `new_session` before prompting; built-in tools and discovery are disabled.
- The only AI-side capabilities are `ocr_image` and the restricted OopsNote MCP pipeline.
- `skills/` is the only editable skill source. `.pi/skills/` is generated by the Pi setup sync.
- OopsMark v1 is the canonical content format. Read `docs/oopsmark-v1.md` before changing content parsing, AI output, Web rendering, Obsidian output, or paper export.
- Hermes remains only as a migration fallback. Do not add Hermes-only behavior or automatic Pi-to-Hermes fallback.

## Source layout

```text
oopsnote/core/       storage models, stores, tags, search, assets
oopsnote/content/    OopsMark parsing, validation, adapters
oopsnote/ai/         managed lifecycle and Pi/Hermes backends
oopsnote/api/        FastAPI composition and route modules
oopsnote/mcp/        Python MCP tools and pipeline write boundary
oopsnote/obsidian/   JSON to Obsidian synchronization
oopsnote/paper/      paper templates and export support
frontend/            Next.js Web application
skills/              editable OopsNote skill sources
scripts/             setup, benchmark, diagnostics, legacy tools
tests/               Python regression suite
storage/             local runtime data; never treat as generated trash
vaults/              user-owned source and Obsidian data; never delete
```

## Development rules

- Preserve existing worktree changes and user data.
- Use the project interpreter: `.venv\Scripts\python.exe`.
- On Windows, give pytest a workspace-local `--basetemp` path.
- Keep REST, MCP, Core, and frontend responsibilities separate.
- Do not store API keys in tracked files or make environment variables the default local-secret flow. Pi auth and `.pi/extensions.json` are local ignored configuration.
- `.pi-rust/` has independent ignored binary, auth, cache, and session state; OMP is retired.
- Keep task timeout, heartbeat, cancellation, stale recovery, retry policy, and finalize checks in the shared managed lifecycle.
- A failed Pi run may be retried only as a fresh run. Never switch backend inside a run.
- Raw RPC logs and task data remain local under `storage/`.
